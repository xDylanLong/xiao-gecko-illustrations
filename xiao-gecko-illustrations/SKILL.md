# 小gecko 配图

## 核心定位

把正文里的核心判断、认知转折、流程、状态或隐喻，变成一张清爽、怪诞、可读但不说明书的手绘解释图。默认视觉 IP 是“小 gecko”：奶油白身体、浅棕斑纹、深色大圆眼、头部尖耳/鳞片轮廓、细小四肢和长尾巴。小 gecko 不是装饰贴纸，而是正在认真参与系统运转的角色。

这套 skill 基于 Ian 小黑配图的工作方法，但必须使用小 gecko 角色，不要出现黑色小怪物或旧案例中的小黑形象。

## 参考资源

按任务需要读取，不要一次塞满上下文：

- `references/gecko-ip.md`：小 gecko 的外形、颜色、动作、性格和禁忌。
- `references/style-dna.md`：纯白背景、线稿、留白、颜色和文字规范。
- `references/composition-patterns.md`：结构类型、原创隐喻和避免复刻的规则。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后的检查和迭代标准。
- `assets/gecko-reference.png`：用户提供的三视图角色参考图。生图时作为角色外形锚点使用，不要把三视图本身直接拼进成图。

## 工作流

### 1. 消化正文

提炼核心观点、认知转折、输入输出、分流关系、前后状态或承接路径。不要平均配图，优先选择一个“认知锚点”。短内容通常生成 1-3 张，长文也不要轻易超过 9 张。

### 2. 先出配图策略

只有用户要求分析配图、shot list 或配图建议时，先输出简短策略。每张说明放置段落、主题、核心意思、结构类型、小 gecko 在做什么、主要元素和短标注词。

如果用户明确说“生成 / 输出 / 做图”，直接用内置 `image_gen` 逐张生成，不要停下来等确认。每张图只讲一个核心结构，不要把多张图拼成一张。

### 3. 单张生成

每张提示词必须包含：

- 16:9 横版中文正文配图。
- 纯白背景、黑色手绘线稿、轻微抖动的笔线、大量留白。
- 小 gecko 作为核心动作主体，外形参考 `assets/gecko-reference.png`。
- 少量红色、橙色、蓝色中文手写批注。
- 禁止 PPT、正式流程图、商业插画、复杂架构、科技 UI、幼稚卡通和左上角类型标题。

小 gecko 必须在画面中做能解释概念的动作，例如扛、推、塞、捞、拧、修补、称重、守门、搭桥、开门、记录或被卡住。若去掉小 gecko 后图的核心隐喻仍然完全成立，说明它太像装饰，需要重写提示词。

每次都从当前正文重新发明低科技、奇怪但成立的隐喻。可以使用纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘或黑盒，但只选 1-2 个主要物件，不要堆满画面。

### 4. 检查与迭代

生成后读取 `references/qa-checklist.md` 检查。出现角色变成普通蜥蜴、画面太满、像 PPT、文字太多、背景不白、角色只站旁边或误出现小黑时，优先定向编辑或重生成。

### 5. 保存交付

如果任务在 workspace 内，把最终图复制到：

```text
assets/<article-slug>-illustrations/
```

按顺序命名，例如：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不覆盖已有资产，除非用户明确要求替换。交付时说明生成数量、每张图用途和保存路径；如果只有一张，直接指出它最适合作为哪个正文认知锚点。
