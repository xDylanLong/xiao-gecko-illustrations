# 自定义角色配图

## 核心定位

把一张用户提供的角色三视图，包装成一套可以反复使用的中文正文配图 skill。输出的是一个新的、可独立安装的 skill，不修改也不覆盖 `xiao-gecko-illustrations` 或其他已有角色 skill。

默认继承小gecko 配图的通用方法：先找正文认知锚点，再为它发明一个低科技、怪诞但成立的隐喻；但最终画面必须使用用户自己的角色作为核心动作主体。

## 输入要求

至少需要一张清晰的正面/侧面/背面三视图，PNG、JPG 或其他 Codex 可读取的图片格式都可以。三视图可以是角色表、白底参考图或同一角色的多个姿态。

可选输入：

- 角色名称或希望使用的 skill 名称
- 角色的性格、动作偏好和禁忌
- 是否继续使用纯白手绘、16:9 横版和少量中文批注
- 是否生成一张 demo 作为新 skill 的示例

如果没有三视图，先请用户上传；不要凭空把一个文字描述当成稳定的角色参考。

## 工作流

### 1. 检查三视图

使用 `view_image` 查看用户提供的图片。记录正面、侧面和背面都稳定出现的特征：轮廓、比例、颜色、斑纹、眼睛、嘴、四肢、尾巴、配件和最容易识别的符号。

不要把三视图截图直接拼进最终配图。它只负责锁定角色身份。

### 2. 提取 character DNA

读取 `references/character-dna-template.md`，把稳定特征整理成简短的角色规范。区分“必须保持”的身份特征和“可以随动作变化”的姿态特征；不要把某一个视图里的偶然姿势误写成硬约束。

### 3. 创建独立 skill

使用 `custom-<slug>-illustrations` 作为默认目录名；如果用户给了明确名称，转换成小写连字符 slug。创建在用户当前 workspace 或用户指定的位置，不要默认写入已经存在的角色 skill 目录。

新 skill 至少包含：

- `SKILL.md`：触发条件、正文配图工作流和角色硬规则
- `agents/openai.yaml`：界面名称、简述和默认调用句
- `assets/<character>-reference.png`：用户提供的三视图原图
- `references/character-dna.md`：稳定外形与动作规范
- `references/prompt-template.md`：引用该角色的单张生图模板
- `references/qa-checklist.md`：角色一致性和画面质量检查

参考 `references/custom-skill-template.md` 组织文件。若需要 demo，另外创建 `examples/images/` 和 `examples/prompts.md`，不要把 demo 混进角色参考资产目录。

### 4. 改写生图约束

保留通用的 16:9、纯白背景、手绘线稿、留白、少量颜色和单一核心结构原则，除非用户明确要求其他风格。将所有“小黑”或“小 gecko”描述替换为新角色的 character DNA；不得遗留旧角色名称、旧角色颜色或旧角色动作禁忌。

每次生成时都要把三视图作为角色参考输入，并明确：角色必须承担核心动作，三视图本身不能出现在最终画面。

### 5. 验证和交付

运行 `quick_validate.py` 检查新 skill 的 frontmatter 和目录名。检查新角色是否能在正面、侧面、背面保持识别度，是否误变成普通动物、通用吉祥物或旧角色。

交付时报告：新 skill 名称、保存路径、参考图路径、是否生成 demo，以及可复制的安装命令。若目标目录已存在，先停止并告知用户，不要静默覆盖。

## 角色硬规则

- 用户三视图是唯一外形锚点；不凭空增加会改变身份的眼睛、耳朵、尾巴、服装或纹理。
- 角色要参与核心动作，不能只是站在画面边缘。
- 保留用户明确要求的颜色、材质、斑纹、配件和表情气质。
- 不要把三视图做成最终构图，不要出现角色表、参考框或“正面/侧面/背面”文字。
- 不要复制小黑、小 gecko 或其他已安装 skill 的角色资产。
- 一张图只讲一个核心结构，中文标注保持短而少。

## 可选调用示例

```text
Use $custom-character-illustrations。
我上传了一张原创角色三视图，请基于它创建一个独立的“我的角色配图” skill。
保留 16:9、纯白手绘、留白和怪诞隐喻的方法，但不要使用小黑或小 gecko 的形象。
角色名：小火苗
请生成 skill 文件、角色规范、提示词模板、QA checklist，并做一张 demo。
```
